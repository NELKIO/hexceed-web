# План продолжения (CPU-тяжёлое — отложено до команды владельца)

Всё ниже требует генерации или массовых симуляций уровней. Запускать по одной задаче,
с `nice -n 19`, vitest — `--maxWorkers=2`, без параллельных агентов.

## 1. Пересборка кампании (`npx vite-node scripts/build-levels.ts`, ~5 мин)
Код генератора уже обновлён, но `src/levels/campaign.json` ещё старый. После пересборки:
- снять `it.skip` с теста `follows the calibration` в `tests/campaign.test.ts`;
- миры 1 ≤ 45 клеток, 2 ≤ 60, 3 ≤ 80; миры 1–3 не шире 7 столбцов, дальше ≤ 9 (витрины ≤ 11);
- «Пустоты» учить во 2-м мире (сейчас w01-12);
- финалы миров (wXX-12) ≤ 110 клеток (w14-12 ≤ 160), трудные шаги распределены по всему решению
  (самый длинный тривиальный отрезок ≤ ~25 клеток), рейтинг финала ≥ предыдущего уровня;
- сделать один прогон и посмотреть таблицу; не крутить настройку десятками пересборок.

## 2. Проблема «Тишины» (blank) — от владельца
На скриншоте задачи дня №1 (22.11.2026) много соседних «—»: человеку непонятно, что отмечать,
хотя решатель считает поле решаемым. Гипотезы и что сделать:
- решатель проходит такие места через счётчик или перебор 4-го уровня — для человека это
  выглядит как угадайка. Ограничить вклад tier-4/счётчика в задаче дня и ранних мирах;
- «Тишина» не должна стоять кучно: не больше 1 «тишины» среди соседей другой «тишины»,
  доля ≤ 10–12 % безопасных клеток (сейчас в поздних мирах 20–27 %);
- у каждой закрытой клетки на границе тумана должна быть хотя бы одна информативная подсказка рядом;
- проверка: прогнать задачу дня за 30 дат и все уровни миров 3–14 с метрикой «есть ли ход
  tier ≤ 2 на каждом шаге без счётчика»; уровни с провалами — перегенерировать.

## 3. Проверки генерации
- задача дня: рейтинг 4–6, ≤ 0,5 с в Node; бесконечный режим: лёгкий 1–2, средний 3–5,
  сложный ≥ 5, эксперт ≥ 7 (тест уже есть, перепроверить после правок «Тишины»);
- задача дня и бесконечный режим получают только механики, которые игрок уже встретил.
